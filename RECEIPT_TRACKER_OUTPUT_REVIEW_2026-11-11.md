# Receipt tracker: overflowing metadata must remain an unknown observation

uxp-labs linked its existing gateway tracker from
[network issue 49](https://github.com/flop-labs/network/issues/49#issuecomment-6735530429).
We inspected its implementation, shared rules and earlier numeric/audit fixes,
then tested exact commit `3df6e3375d19b50e5f9f818cacd96e9d9c9ab5fb`.
This extends their tool; it is not a replacement tracker or a new native
submission-evidence-kit pilot. No original signed Technocore job packet was
established for this lead.

## Reproduction and proposed repair

The [existing receipt reporter](https://github.com/uxp-labs/flop-devnet-lab/blob/3df6e3375d19b50e5f9f818cacd96e9d9c9ab5fb/spend-guard/receipts.py)
promises an unknown error observation rather than a crash on malformed data.
Its amount validator already handles non-finite spends. However, it copies
`request_id`, `state` and `terminal_event` without validating their JSON output
representation. This synthetic saved response reproduces the adjacent gap:

```json
{"request_id":"saved-fixture","state":"estimated","settled_spend":null,"terminal_event":{"value":1e999}}
```

The number is syntactically valid JSON, but Python's decoder converts it to
infinity. The final `json.dumps(..., allow_nan=False)` raises `ValueError` and
prints no row. A list can therefore stop before later valid receipts, and
the same issue affects malformed `last_known` metadata on an expired-key read.
This is an offline synthetic counterexample, not an observed gateway response,
financial loss or settlement defect.

The [two-file companion patch](research/uxp_receipt_json_output_2026_11_11.patch)
handles that serialization boundary once. It emits
`{"error":"non_finite_json","state":null}` for the affected observation,
retaining HTTP and expiry flags generated by the reporter itself. It prints
neither the malformed packet nor an amount of zero. Later valid list entries
still print. Finite metadata, large integers, Unicode, numeric-looking strings
and the existing invalid-spend classification are preserved. This deliberately
rejects the affected observation rather than claiming which malformed field
the gateway meant.

The change does not alter request routing, redirect policy, credentials,
amount validation, receipt identity reconciliation or any spending/ledger path.
The existing `get()` is replaced in our new tests; it performs no network read.
This boundary is not a general resource-limit, malformed-file or secret audit.

## Validation

Tests ran with Python 3.14.3 on macOS arm64. Six added methods cover nested
overflow/NaN/infinity in copied metadata, good rows adjacent to a bad row,
existing invalid-spend handling, finite/Unicode controls and both malformed
and valid `last_known` observations. On unchanged source, three methods expose
14 errors, while the other three controls pass. The candidate passes all six.

The original spend-guard suite passes 66 tests. With the companion patch it
passes 72, including the new six and the original redirect/non-finite amount
controls. Existing resource warnings about file handles remain separate.
Native network access was denied for the initial boundary reproduction; the
full spend-guard suites allowed loopback for their existing HTTP tests.
Only synthetic credentials were supplied. No estimate, enrollment, inference,
faucet, signature, purchase or paid action was performed. The TypeScript and
viewer suites were not run for this Python-only change.

The patch applies cleanly to a fresh pinned tree and yields bytes identical
to the tested candidate. No dependency installation is required:

```bash
git clone https://github.com/uxp-labs/flop-devnet-lab.git
cd flop-devnet-lab
git checkout 3df6e3375d19b50e5f9f818cacd96e9d9c9ab5fb
# Save and inspect the linked patch, then use its actual local path.
git apply --check /path/to/uxp_receipt_json_output_2026_11_11.patch
git apply /path/to/uxp_receipt_json_output_2026_11_11.patch
python3 -B -m unittest discover -s spend-guard -q
```
